# 使用指南

完成[部署与首次登录](../README.md#首次登录)后，可以在上传页上传，在图库检索和整理。客户端集成见 [API 指南](api.md)，已有部署的兼容性变化见[升级指南](upgrading.md)。

## 图片上传与处理

支持文件选择、拖拽、剪贴板图片粘贴及 HTTP / HTTPS 图片 URL 导入。上传前可选择可用的存储桶和标签；每批最多 10 个文件，每个文件独立显示结果，部分失败不代表整批失败。

新增图片仅接受真实的 JPEG、PNG、GIF 和 WebP，不能通过修改扩展名上传 SVG 或未知格式。界面可设置图片大小、允许类型、压缩质量、WebP 转换、缩略图和跳过压缩格式；服务器还会执行独立的尺寸预算，默认最多 40,000,000 像素、单边 16,384 像素。

原图模式、跳过压缩和动画 WebP 同样需要通过格式和尺寸验证。有效动画 WebP 保留原始字节；无法识别尺寸或截断的文件会被拒绝。图像处理并发固定为 1，遇到处理繁忙时稍后重试，不要连续无间隔重发。

内容哈希用于识别重复图片。去重命中时复用已有记录，不重复增加数量。原始文件名作为元数据保留，新文件的物理名称带随机标识，不应依赖“同名上传会覆盖旧图”的行为。

URL 导入仅用于图片，且不能访问被禁止的内网地址。批量上传、大小限制与错误码见 [API 指南](api.md#上传图片或视频)。

## 视频上传与播放

在“系统设置 → 上传规则”打开“允许视频上传”后，可以通过文件选择、拖拽或 API 上传 MP4 / WebM。该功能默认关闭，启用后仍受用户上传权限与存储桶权限约束；关闭开关不会影响已有视频的播放、管理和统计。

- 视频大小限制独立于图片，默认 **100 MiB**，可设置为 **1 MiB～1 GiB**。
- 保存原文件，不转码、不压缩、不生成服务端封面，不需要 FFmpeg。
- URL 导入、剪贴板图片粘贴和 `import-local` 仍只处理图片。
- 容器格式不代表编码一定兼容。建议使用 H.264 MP4 或 VP9 WebM，实际能否播放取决于浏览器。

上传页和图库显示视频占位卡片，点击后通过浏览器原生控件播放，加载元数据后显示时长和分辨率。应用代理支持 `HEAD` 和单段 `Range` 请求；独立直链或 CDN 也必须支持 Range，才能按需读取和拖动播放。

## 存储与访问

可使用本地、S3/R2、WebDAV 或 FTP。管理员配置存储桶并分配使用权限；普通用户只能选择自己有权使用的桶。本地存储可配置 CDN 域名，S3/R2 可配置图片直链域名。

### 存储路径与文件名

“系统设置 → 存储与上传”中的存储路径和文件名模板对所有存储生效，只影响新上传的文件。可用变量为 `{year}` `{month}` `{day}` `{hour}` `{minute}` `{second}` `{role}` `{random}` `{uuid}` `{filename}`，区分大小写；存储路径不能包含空格、`\`、`.` 或 `..` 目录。

本地存储的文件始终放在 `uploads` 目录下，路径不以 `uploads` 开头时自动补上，以保证文件位于持久化目录内、本地 CDN 域名也能生效。S3/R2 等远端存储按原样使用配置的路径。文件名除单独使用 `{random}` 或 `{uuid}` 外，都会自动加上 `-随机ID`，避免重名。

### 停用与删除存储

不再向某个存储上传时，优先使用**停用**：停用后它不出现在上传选项中，上传和 URL 导入都会被拒绝；已有图片、外链、授权和远端文件保持不变，可随时重新启用。本地存储和当前系统默认存储不能停用，需先在“系统设置 → 存储设置”切换默认存储。

**删除**会移除该存储的全部图片记录、标签关联和用户授权，外链随之失效，且无法撤销。删除时默认保留远端文件，便于自行备份或迁移；只有勾选“同时删除远端文件”（API 为 `purge_objects=true`）才会清理其中未被其他记录引用的源文件和缩略图。当前系统默认存储同样不能删除。

更换远端端点或账户时，需要显式提供新凭证。引用已有配置进行连接测试还要求 `storage:update` 权限，只有新建权限不等于可以使用已保存的凭据。

数据库记录与物理对象需要共同备份。删除记录时，应用会检查历史共享对象的主图 / 缩略图引用，不能手工删除某个物理文件来代替图库管理。覆盖与删除保护的边界见[对象与存储兼容性](upgrading.md#对象与存储兼容性)。

媒体外链用于公开读取；管理界面的登录和权限不等同于私有媒体访问控制。来源白名单也不能代替身份认证，分享前应确认内容可公开。

## 标签与搜索

图库可以组合使用媒体类型、存储桶、标签和未分类筛选，并按文件名、URL 或内容哈希搜索。管理员还可按上传者角色筛选。

勾选文件后可批量增删标签、复制链接或删除文件；可用操作取决于当前账号权限和资源归属。标签管理的权限与给文件添加 / 移除标签的权限分别检查。

## 复制外链

上传页的上传结果、预览和图库支持复制链接；图库可批量复制：

| 格式 | 图片 | 视频 |
| --- | --- | --- |
| URL | 直接链接 | 直接链接 |
| Markdown | 图片语法 | 普通链接，不是图片语法 |
| HTML | `<img>` | 带 `controls` 的 `<video>` |
| BBCode | `[img]` | `[url]` |
| 动图式 HTML | 普通图片 | 静音循环、自动播放的 `<video>` |

视频不能用 `<img>` 或 Markdown 图片语法嵌入。接收方站点是否允许 `<video>`、自动播放及跨域资源，仍取决于该站点与浏览器的规则。

## 统计口径

- 图片数量与视频数量分开显示；API 的 `total_images` 只计图片，`total_videos` 计视频。历史缺少 MIME 的记录继续归为图片。
- 图片体积只计主文件，视频体积只计原文件，不含缩略图；存储桶占用包含成功保存的缩略图。
- 今日 / 本月上传附图片与视频分类；趋势中的 `count` 为两类合计，另有 `image_count`、`video_count`。
- 数量按当前记录统计，去重不重复计数，删除后会减少。记录口径不等于底层物理对象去重后的磁盘占用。

## 导入历史本地图片

`import-local` 将现有 `uploads` 下的图片登记到图库，不移动或重命名原图，也不改变原始主文件 URL。只扫描 JPEG、PNG、GIF、WebP，跳过缩略图目录；新增缩略图使用独立随机名称。导入仍受图片大小、格式和尺寸限制。

先备份 `data` 和 `uploads`，确认目标用户 / 存储桶，再停止正常服务，避免两个进程同时写数据库和存储。以下示例适用于[现有 Compose 部署](deployment.md#使用-compose-从源码部署)，使用已经构建的同一版本：

```bash
docker compose stop oneimg
docker compose run --rm --no-deps oneimg ./main import-local --root /app/uploads --dry-run
```

核对预览统计后再正式执行，完成后恢复服务：

```bash
docker compose run --rm --no-deps oneimg ./main import-local --root /app/uploads
docker compose start oneimg
```

`--dry-run` 不写导入记录或缩略图，但命令仍会先执行应用初始化和启动迁移，不是整个应用的只读模式；需要完全隔离时，应对备份副本操作。

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--root` | `./uploads` | 历史本地图片根目录；容器内通常为 `/app/uploads` |
| `--user-id` | `1` | 图片归属用户，确认该用户存在 |
| `--bucket-id` | `1` | 对应本地存储桶，不用于导入远端桶 |
| `--date-source` | `mtime` | `mtime` 使用文件时间，`path` 尝试目录年月日并回退到文件时间，`now` 使用当前时间 |
| `--update-existing-date` | 关闭 | 更新已入库图片的时间，先配合 `--dry-run` 核对 |

已有记录一般跳过；缺失的哈希、原始文件名或原始大小可能被补全。退出码非零时检查失败计数和日志，不要假定全量导入成功后直接清理原文件。
